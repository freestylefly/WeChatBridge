## 优先修复的问题

### B01 · P1：关闭场景选择器仍可能执行粘贴

位置：`CollectionWindow.xaml.cs:207`、`MainViewModel.Collections.cs:109`、`MainViewModel.cs:690`、`SceneCoordinator.cs:162`、`ScenePickerWindow.xaml.cs:43,159-162`。

选择目标菜单项后立即隐藏浮条并冻结成员，再调用普通转发的场景选择流程。场景窗口的关闭、Escape 与“直接转发”都返回 `ScenePickerAnswer.Cancelled`；协调器将取消转成没有场景的 Ready 结果，后续仍可调用 `Delivery.DeliverAsync`。因此当该收集触发场景选择器时，用户关闭窗口并不能回到继续收集，而可能直接激活目标并粘贴附件。

设计要求关闭 / Escape 等价继续收集。应提供独立的交付确认面板，区分取消和明确选择不带场景；仅在最终主按钮点击后冻结成员。

### B02 · P1：分批接收会改写剪贴板

位置：`ShareTarget/Program.cs:357`。

`ProcessShareAsync` 提交完成后无条件调用 `TryWriteClipboard`，包括统一入口中选择分批收集的分享。这会覆盖用户原有剪贴板，违反设计“收集过程不写入剪贴板”。应依据最终选择的 action 跳过 Collect 的正常剪贴板写入，单独处理用户明确要求的复制与失败兜底。

### B03 · P1：缺少“仅保存原始 ZIP 到本次选择的文件夹”

位置：`MainViewModel.Collections.cs:128-138`。

Folder 与 Obsidian 都调用 `KnowledgeDelivery.Deliver`，前者也要求预先配置目录，生成 Markdown 并提取媒体。原件会被保留，但这并不是设计中的只交付原包。已有 `FolderDelivery.Save` 未接入收集交付界面；缺少本次选择文件夹和取消后留在面板的流程。

应将原包保存与笔记归档区分为明确的操作，原包保存禁用场景，按添加顺序复制原始文件并处理同名冲突。

### B04 · P1：批次“删除”无法从系统回收站恢复，连续删除只保留一个撤销入口

位置：`CollectionService.cs:76-110`、`CollectionWindow.xaml:72-74`。

删除将 Ready 批次目录移动到应用内部 `RemovedCollectionBatches`，并覆盖单个 `collection-undo.json`；不是系统回收站。再次删除会覆盖前一批的恢复记录，前一批又不在 `LoadBatches()` 读取的 Ready 中，因此历史页与系统回收站均无法找回它。字节仍在内部目录，但只能人工查找。整组删除也没有 UI 或服务实现。

设计分别要求“移出本次收集但历史仍可找到”和“删除到系统回收站并可撤销”。应提供两个明确操作，补齐整组删除，确保连续操作后仍有可用的恢复路径。

### B05 · P2：场景选择复用单批规则，无法保证本次显式选择

位置：`MainViewModel.Collections.cs:126,147-150`、`SceneCoordinator.cs:132-192`。

多个群的聚合 `ChatName` 为 null；在没有 pending 选择或可恢复群名的情况下，普通解析流程不弹场景选择器，可能直接无场景交付。同群已有绑定时则可能直接使用绑定场景。均缺少设计要求的同屏目标单选、场景下拉和默认“直接交付，不附加场景”。设置中也没有上次明确目标 / 场景的记忆字段。

此外场景上下文仅由聚合批次的第一个 ID 写入；其余成员只记录 action / outcome，整组历史搜索又未包含 `c.SceneName`，场景追溯和搜索不完整。

### B06 · P2：无法主动保存为待发送或开始新的收集

位置：`CollectionWindow.xaml`、`CollectionWindow.xaml.cs:185`、`BatchCollection.cs:65-78`、`HistoryPane.xaml`。

账本有 `ParkCurrent` / `Resume`，但 UI 只有恢复操作，缺少“保存为待发送”和“开始新的收集”。恢复旧组时会将当前组转为 Draft，却没有告知后续追加目标。用户误收后也不能仅解除归属。

### B07 · P2：浮条缺少整组统计和首尾查找操作

位置：`CollectionWindow.xaml.cs:27-31,78-117`、`CollectionWindow.xaml:40-93`。

浮条摘要只有批数和字节数，没有约消息数、部分批次未知统计或上一批完整时间范围。首尾仅提供第一条 / 最后一条，缺少较早 / 较晚各两条及“复制关键词”。顶部短预览仅显示 HH:mm，日期需查看管理详情 / tooltip。没有 ≤5 批标签、>5 批下拉和保留旧批浏览位置；每次 Refresh 都重建批次列表并将顶部参考绑定为最新批次。

TXT 失败会保留原 ZIP，并在管理详情给出未知条数和边界说明；这是已实现的降级，但摘要和查找交互仍需补齐。

### B08 · P2：会话识别补充要求只实现了一部分

位置：`ShareTarget/Program.cs:337-343`、`MainViewModel.cs:221-225,626`、`CollectionWindow.xaml`。

已接入 UIA 标题读取、窗口标题回退、批次名称持久化、手工编辑及显式默认名称。预取在整个 ZIP staging 完成后才发出，未证明是导入开始时的标题快照。缺少 OCR 回退、识别进度及旧批次明确点击“识别当前微信”的入口。UIA 不要求微信在前台，但最小化等真实窗口状态仍需实机验证。

### B09 · P2：历史卡片不满足当前组置顶与组内展开

位置：`MainViewModel.Collections.cs:15-21`、`HistoryPane.xaml`。

收集卡按创建顺序倒序展示，恢复较老收集后当前组不会置顶。卡片仅有名称、批数、状态和查看 / 改名，缺少大小、上批范围、直接完成交付、更多菜单与内联批次清单。现有实现会将成员从普通历史列表排除，磁盘统计按真实批次计算，未重复统计。

### B10 · P2：操作屏幕、窄屏和深色适配尚不符合要求

位置：`CollectionWindow.xaml:5`、`CollectionWindow.xaml.cs:123-137`、`Themes/AppTheme.xaml:16-55`。

浮条固定 Width=400，定位 / 拖动边界使用主屏 `SystemParameters.WorkArea`；不是微信操作所在显示器，也没有避开分享弹窗或鼠标的逻辑。主题使用固定浅色 StaticResource，没有浅深色分支。已有渲染测试仅覆盖普通字号、400 宽浮条和中英文；320 px、大字、混合 DPI / 多屏及完整键盘流程尚未验证。

## 验收场景映射

1. 6 条直发不进入收集、6 条分批可立即交付：action 逻辑已对应；实际微信操作待验，交付前须按补充要求补齐名称。
2. 100 / 100 / 86 不自动结束：账本无条数切换逻辑；未运行此完整微信流程。
3. 首尾参考供人工查找、浮条不改变焦点：不主动激活已实现；批次切换和复制关键词缺失，真实焦点待验。
4. 视频 ZIP 原样保存，TXT 失败不中断：核心逻辑及坏 TXT / ZIP 降级已覆盖；真实视频附件端到端接收待验。
5. 隐藏 / 重启恢复：服务及 UI smoke 已覆盖，隐藏不会暂停收集。
6. 单批失败不回滚前批：原子落盘机制已有，指定浮条错误交互缺失。
7. 取消可继续收集、失败可重试：重试已覆盖；取消存在 B01，未通过。
8. 冻结时后来批次进入新组：服务测试已覆盖；实际交付中浮条新组反馈待验。
9. 移出不删原件、未完成组免清理：免清理已覆盖；独立移出操作缺失，删除恢复存在 B04。
10. 320 px、浅深色、大字和键盘：仅中英文常规尺寸渲染通过，其余未通过或待验；macOS 14 条件不适用于 Windows。
