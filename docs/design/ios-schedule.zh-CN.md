## 2. 关键路径与可并行的任务

```
T0.1 ─┐
T1.1 ─┼─▶ T2.1 ─▶ T3.1 ─▶ T3.2 ─┐
T1.2 ─┘          └─▶ T3.3       ├─▶ T5.3 ─▶ T6.1 ─▶ T7.1 ─▶ T8.1 ─▶ T8.2 ─▶ T8.3 ─▶ T9.1 ─▶ T9.2
                  T5.1 ─▶ T5.2 ─┘          ▲
                  T4.1 ────────────────────┘
```

- **关键路径**：T1.1 → T2.1 → T3.1 → T3.2 → T5.3 → T6.1 → T7.1 → T8.x → T9.1。
- **可以提前做、不依赖模拟器的任务**：T1.2、T1.4、T4.1、T5.1、T5.2（纯逻辑和 Core 改动，用 `swift test` 加类型检查就能验证）。如果 T0.1 被卡住（磁盘、用户未同意），先做这几个，不要空等。
- 如果有第二个执行者：一人走关键路径；另一人做 T1.2 → T4.1 → T5.1 → T5.2 → T7.1 的逻辑部分。两人改的文件不重叠：Core 改动（T1.2、T4.1）由同一人负责，避免冲突。

## 5. 风险与应对

| 风险 | 可能性 | 影响 | 应对 |
|---|---|---|---|
| 磁盘不够装 iOS 平台（剩 17 GB，平台约 8–9 GB） | 中 | M0 卡住 | 先删旧运行时（7.9 GB）；仍不够时请用户清理；同时先做不依赖模拟器的任务（§2） |
| 没有付费签名，App Group 在真机上用不了 | 中 | M6 卡住 | 模拟器上能完成 S1–S11；真机项标「待真机」，交付推迟到账号就绪 |
| 豆包、千问一次只收第一个附件或丢掉文本 | 中 | 投递体验变差 | `maxAttachments` 分组发送已经在设计里；提示词有剪贴板兜底 |
| 大 ZIP 让分享扩展超过内存上限 | 低 | 收不进来 | `AttachmentImporter` 走文件表示流式复制；R6 专门测；如果还是崩，扩展里改成只复制、不读入内存 |
| 多人群样本的占位写法与假设不同 | 中 | 详情页渲染错误 | `MessageToken` 不认识时按原文显示，不丢内容；R1 后补规则 |
| Swift 6 严格并发在 SwiftUI 层产生大量告警 | 中 | 进度变慢 | 主 App 允许降到 Swift 5 模式（开发文档 5.3），Core 保持 Swift 6 |
| 本地包引用 `../macos` 时 Sparkle 解析失败（离线） | 低 | 无法构建 | 联网解析一次即可；仍有问题时执行 Q4（把 Core 抽到 `shared/`），工期 +1 天 |

## 6. 进度汇报格式

每完成一个任务，在对话里用下面的格式汇报一次；每个里程碑结束时，把同样的内容追加到 `docs/design/ios-验收记录.zh-CN.md`：

```
[任务] T3.2 中转站列表
[状态] 完成 / 阻塞 / 进行中
[提交] <短 SHA> [AI] feat(ios): …
[验证] swift test 186/186（1 跳过）；类型检查 OK；xcodebuild test 23/23；S2 S10 通过
[未验证] 无 / 列出原因
[下一步] T3.3
[需要用户] 无 / 具体事项
```

阻塞超过半天就立刻汇报，同时切换到 §2 里不依赖它的任务。

## 7. 变更规则

- 工期变化超过 1 天：更新本文件 §1 的表，并在汇报里说明原因。
- 产品范围变化（加功能或砍功能）：先问用户；同意后同时改开发文档 §9、§10、§12 和本文件。
- 真机结果推翻了能力表或数据格式的假设：改开发文档 §3 和 §6.6，并在验收记录里注明依据。
